# Bot 好友申请

自动处理好友申请，但**只同意看起来是真人的账号**——等级够高、开过会员、或是老号（短 QQ 号）。其余申请不直接通过，而是把对方信息私聊发给主人，主人回复「同意 QQ号」或「拒绝 QQ号」后再真正处理。

## 判定顺序

```
黑名单         → 直接拒绝（附言可选）
白名单         → 直接同意
QQ 等级 ≥ 阈值 → 同意
会员账号       → 同意
QQ 号 ≤ N 位   → 同意（老号）
其余           → 发给主人裁决
```

三档默认线：**等级 ≥ 16**（一个太阳）、**会员直接过**、**QQ 号 ≤ 9 位算老号**，三选一满足即可。

## 为什么这样判

| 信号 | 意义 |
|---|---|
| QQ 等级高 | 长期使用、有真实社交行为，批量小号很难养到 16 级 |
| 会员 | 付费账号，成本高，小号不会买 |
| QQ 号位数少 | 注册越早号越短，9 位以下基本是老用户 |

低等级 + 非会员 + 长号，绝大多数是临时注册的号，不适合直接放进好友列表。

## 可疑好友申请（NapCat 扩展）

QQ 会把一部分申请降级成**可疑好友申请**：不会再发 OneBot 的 `request` 事件，而是以一句私聊系统消息「请求添加你为好友」出现。只监听 `request` 事件会漏掉这类申请，机器人甚至会把这句系统消息当普通聊天来回复。

v0.1.1 起同时处理两种：

- 普通申请：`set_friend_add_request`（可同意/拒绝）
- 可疑申请：收到系统消息后查 NapCat 的 `get_doubt_friends_add_request`，按 QQ 号找到对应 `flag`，再调 `set_doubt_friends_add_request` 同意

注意：`set_doubt_friends_add_request` **只能同意、不能拒绝**。遇到黑名单或不达标的可疑申请，插件不会动手，只私聊告知主人「建议手动拒绝 / 只能手动同意」。这类系统消息**不拦截**——跟还没加上好友的人警惕地聊几句是允许的。

## 主人裁决

自动判定没通过的申请，插件会把信息私聊发给主人（昵称、等级、会员、QQ 号、申请附言、没通过的原因）：

```
收到好友申请：3559682238（千寺狐.，18 级）
没有自动通过：等级/会员/老号都不满足
回复「同意 3559682238」通过，或「拒绝 3559682238」拒绝（7 天内有效）。
```

- 主人回复 `同意 3559682238` / `拒绝 3559682238` 才执行；**必须带 QQ 号**，避免和正常聊天里的「同意」混淆
- 只认主人/管理员（网页测试台也算），其他人回这类命令无效
- 挂起记录有 TTL（默认 7 天，QQ 申请 flag 会过期），过期自动清理
- 可疑申请只能「同意」；回复「拒绝」会提示去 QQ 里手动处理
- 手动裁决不占每日自动通过额度

## 其他保护

- **每日自动通过上限**（默认 5 个），超出后当天剩余申请一律转主人裁决，防批量刷号
- 自动通过或手动裁决后都会**私聊告知主人**
- 黑名单可单独关闭「主动拒绝」，改成只挂起（不暴露"被拉黑"）
- 普通 `request` 事件处理后不会进入对话流程；可疑申请的系统消息不拦截，允许警惕地聊几句

## 配置

| 键 | 默认 | 说明 |
|---|---|---|
| enabled | true | 总开关 |
| min_qq_level | 16 | 等级下限，0 = 不看 |
| accept_vip | true | 会员直接同意 |
| max_qq_len | 9 | 位数 ≤ 此值算老号，0 = 不看 |
| whitelist / blacklist | 空 | 逗号或空格分隔的 QQ 号 |
| reject_blacklisted | true | 关闭后黑名单只挂起不拒绝 |
| max_accept_per_day | 5 | 每日自动通过上限 |
| review_enabled | true | 未自动通过时把对方信息发给主人裁决 |
| review_ttl_hours | 168 | 裁决有效期（小时），超时清掉挂起记录 |
| notify_owner | true | 自动通过/裁决结果通知主人 |
| owner_session | 空 | 通知发给谁，留空取 AstrBot 管理员 |
| reject_comment | 「暂时不方便加好友哦」 | 拒绝时的附言 |

## 依赖

- 纯标准库，无第三方依赖。
- 需要 NapCat 支持 `get_stranger_info`（查等级/会员）、`set_friend_add_request`（普通申请），以及 `get_doubt_friends_add_request` / `set_doubt_friends_add_request`（可疑申请，NapCat 扩展接口）。当前 NapCat 4.18.x 均支持。
- 其他 OneBot 实现没有可疑申请接口时，普通 `request` 事件仍照常处理，可疑申请会被跳过。

## 注意

- 查不到申请者资料时（接口失败），按"等级 0、非会员"处理，也就是会挂起而不是盲目同意。
- 自动通过只在**收到申请时**生效，历史积压的申请需要手动处理。
